**Input**: Design documents from `/specs/008-checks-first-review/` (`spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`)

**Prerequisites**: features 001 to 007 on main (007's code phases T001 to T058). The recorded dumps at `%LOCALAPPDATA%\SwReview\handover\2026-09-20-gui\dumps` exist on the development machine only and never enter the repository; the tasks that read them carry `[D]`. Feature 009's increments 1 to 3 landed on main on 2026-09-23 (`2c48e2b`, `cf3c66e`, `b5cfcb4`) and edited `extractor/SwReview.AddIn/Review/ReviewPage/render.js`, `app.js`, `index.html` and `specs/007-attention-policy-gate/contracts/attention.md`; feature 009's later increments (`specs/009-engineer-workspace/`) keep editing the Review page and render 008's folded group and answer batch, so T032 and T094 to T095 start from main's latest page work and rebase again before they land.

**Tests**: REQUIRED, and **strictly test-first**: every implementation task is preceded by the test task that must be written and must fail first (a characterization test, T051, is the one test written to pass before its change). The tests that go red **by design** when a change lands are named in the task that lands it and edited deliberately there, never loosened (research R2.47 to R2.49). What must not move: the golden reports and rankings (byte-identical except where a session names a folded family, which no existing golden does - FR-029); `EfficiencySettings`' twelve fields and every lever-count pin (until Phase 9's lever 13, which moves them to thirteen deliberately in T107); the `TOOL_FUNCTIONS` pins (32 tools); `chat-events.schema.json`; `test_no_lever_in_pane_settings.py`, `test_docstring_split.py` and `test_prefix_stability.py`, which pass unedited.

**The replay is the gate.** Phase 2 lands it; every later story ends with a task that replays the committed fixtures as its acceptance: T049 (US2), T078 (US3), T086 (US4), T093 (US5). Every replay of a committed fixture, in every test, passes `standards_profile=config/standards.example.yaml` (on the command line `--standards-profile ../config/standards.example.yaml`), the profile the pilot ran when the recordings were made (research R2.10).

**Organization**: Setup (the tokenizer, one serialization, rounds in the fake, the finding key, the test support, the recording reader, the fixtures and their hygiene), Foundational = User Story 1 (the replay), US2 checks first, US3 the model's view, US4 asking and answering, US5 cost, Polish, then the next workstation sitting.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on another unfinished task)
- **[Story]**: `US1` to `US5`; Setup and Polish tasks carry no story tag
- **[D]**: needs the recorded dumps on the development machine
- **[W]**: needs the pilot workstation or a licensed SOLIDWORKS seat - only Phase 8
- **[K]**: needs a provider API key - only Phase 8

## Path Conventions

- Python: `reviewer/src/swreview/`, tests in `reviewer/tests/`; commands run from `reviewer/` with `uv run`
- C#: `extractor/SwReview.AddIn/`, `extractor/SwReview.AddIn.Tests/` (only T094 to T095)
- Contracts: `specs/008-checks-first-review/contracts/` (already written by the plan; a task that lands a behaviour reconciles its contract if the code had to differ); other features' contracts are edited in the task that changes their shape

## Notes

- **The record never shrinks; only the view does.** A task that makes a tool return less, strips a reference from the package or the session, or derives a finding from a stub has misread the feature; the view is computed beside the payload and every result is stored in full.
- **Absent stays absent, and says so.** Every digest, stub and grouped gap states what it left out (`rows_omitted`, `finding_ids_omitted`, `ids_omitted`, `entity_ids_omitted`, `and N more`, `pruned`, `refetch`); every family that could not run is a coverage item and a digest line; the replay labels every estimate and lower bound; an unknown token count is null, never zero.
- **One of each.** One tokenizer, one serialization of a result (`tool_result_text`), one pruning function for both adapters and the replay, one check digest for the guard and the view, one resolver for the command line's settings, one validator for both answer routes, one function deciding the pane's defaults.
- **The command line is off; the pane is on.** Nothing changes for `swreview review` or `benchmark run` unless asked; `--pane-defaults` reproduces the pane in one flag.
- **No thirteenth lever** from the plan. Checks first is lever 5, parallel calls lever 6, and the model-view settings are settings; every lever-count pin stays as it is until the owner's lever 13 (Phase 9).
- **The page is 009's except one function.** `usageLine` is the only page code this feature changes, and it lands last, rebased.
- **The recordings stay off the repository.** Fixtures are generated from them on this machine and checked for leaks before they are written; no recorded path or name goes into a commit message.
