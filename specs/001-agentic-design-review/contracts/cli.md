# Command-Line Contracts

## `swreview` (Python, `reviewer/`)

Installed as a console script by `uv sync`. Exit code 0 on success, 1 on a validation or
runtime error, 2 on usage error. Every command that prints a result accepts `--json` to
print machine-readable output to stdout; human output goes to stdout otherwise,
diagnostics to stderr. Two commands own their stdout instead and take no `--json`:
`chat serve` prints one handshake line and nothing else, and `mcp` uses stdout as the MCP
transport.

The commands that run a model - `review` and `benchmark run` - share three options:

| Option | Values | Default |
|--------|--------|---------|
| `--provider` | `openai`, `gemini` (`fake` is the scripted provider the tests use) | `openai` |
| `--model` | any model id the provider serves | that provider's own default, from `reviewer/src/swreview/agent/settings.py` |
| `--effort` | `low`, `medium`, `high`, `xhigh` | `high` |

`--model` is deliberately optional and no command line carries a hard-coded model id: the
default belongs to the provider and lives in one module, so a run started without `--model`
cannot write the id of a model this product no longer serves into `session.json` (FR-026).
The API key is never an argument. Values saved in the pane's `settings.json` win over the
process environment (`OPENAI_API_KEY`; for Gemini `GOOGLE_API_KEY` ahead of
`GEMINI_API_KEY`), so a workstation that exports a personal key cannot quietly override the
key the engineer entered in the pane; a command line started outside the pane has only the
environment. Which of the two it came from is recorded on the session as `key_source`. The key itself never reaches a session file, a report, a run folder or a log
line (FR-015); `audit-secrets` is the check that says so.

| Command | Arguments | Effect |
|---------|-----------|--------|
| `swreview validate <package_dir>` | | Loads `package.json` against the IR schema and prints gaps and discrepancies. Fails on major version mismatch. |
| `swreview ingest <package_dir>` | `--pdf <file>...`, `--bom <csv>`, `--manifest <json>`, `--step <file>...` | Builds or augments `package.json` from exported files (drawing parse, BOM, manifest). Native data, when present, wins over exported data for the same entity. |
| `swreview review <package_dir>` | `--out <dir>`, `--provider`, `--model`, `--effort` (see the table above), `--bridge`, `--checklist <file>`, `--fail-tool <name>` (test hook), `--max-steps N` | Runs the agent loop; writes `session.json` and `report.md`. |
| `swreview report <session.json>` | `--out <file.md>` | Re-renders the Markdown report. |
| `swreview disposition <run_dir> <finding_id>` | `--decision accepted\|rejected\|deferred`, `--note`, `--by` | Records a disposition and re-renders. |
| `swreview exceptions accept <run_dir> <finding_id>` | `--note` | Creates an `Exception` bound to the finding's geometry fingerprint and configuration. |
| `swreview exceptions list <package_dir>` | | Shows active and needs-review exceptions. |
| `swreview exceptions accept-rms <run_dir>` | `--package <dir>`, `--file <rms_exceptions.json>`, `--by <name>`, `--json` | Imports the checker's flat waiver file `{ "<rule_id>": "<reason>" }` against one `check rms` run: every `demonstrated` finding whose `check` is a listed `fail` rule becomes one `Exception` (`fingerprint_kind: feature_tree`, note = the reason), `exceptions.json` is written, `exception_id` is recorded on the findings and the report is re-rendered. Prints, per rule id, `accepted <n>`, `would accept <n>`, `unused`, `invalid (warn rule)` or `invalid (unknown rule)`; `--json` carries the same four values in `status`. Exit 1 when any id is invalid and **nothing is written** in that case, so a file half of which names warn rules cannot leave a partial waiver set behind. A `warn` rule is refused because only a demonstrated `fail` is acceptable (FR-016). |
| `swreview check fit\|stack\|fastener\|alignment` | `--package <dir>` plus check-specific ids | Runs one deterministic check without the agent; prints the finding. |
| `swreview check interference` | `--package <dir>`, `--json` | Grades a dumped package's interference results without the agent: grouped conditions with status, exception statuses after refresh, unresolved coverage. Read-only; never writes `exceptions.json`. |
| `swreview check rms` | `--package <dir>`, `--document <id>` (repeatable), `--scope part\|assembly\|equations\|all` (default `all`), `--json` | Grades a package against the Resilient Modeling rules without the agent: findings and aggregated coverage in the same shape as the other `check` commands. It runs through `run_rms_check`, the single no-language-model evaluation entry point the Model check tab's `POST /checks/rms` also calls (FR-024), so it writes `session.json` and `report.md` into the package directory and, before the rules run, carries forward the newest `exceptions.json` under the run root whose package carries the same `design_id` (FR-029: no candidate is reported, not an error; a candidate that cannot be parsed refuses the run rather than yielding an empty store). `exceptions.json` beside the package is read and refreshed, so a waiver whose feature tree has moved reads `needs_review` and silences nothing. A package whose `features` array is empty is refused, naming the profile that produced it, rather than reported as 34 unresolved rules that read as a broken part (FR-022). Violations are output, not an exit code: this exits 1 only when the package cannot be read or an argument names something the package does not carry. |
| `swreview rms types` | `--package <dir>`, `--json` | Names every feature type name in the package that `checks/rms_types.yaml` does not classify, with its feature count and the documents it appears in. Calibration, not grading: `GetTypeName2` returns a string SOLIDWORKS promises nothing about, so an unclassified name is neither a pass nor a fail - it is a hole in the table an engineer closes with evidence. Reads the package and writes nothing. |
| `swreview rms suppress-plan` | `--package <dir>`, `--document <id>`, `--out <file>` (default `<package dir>/suppress-plan.json`), `--json` | Writes the suppress-test plan for one part document: the review configuration, the Detail group name, and the Detail content features in tree order (`feature_id`, `persist_ref`, `persist_ref_scope`, `name`, `type_name`), derived from `features[]` by the same group assigner and type table every rule reads. `swreview-extract suppress-test` consumes it, so the extractor decides no folder, group or content and the rule grades exactly the set that was planned. Exit 1 when the document has no `features[]` rows or no Detail group - an empty plan would read as "nothing to suppress" rather than "we never looked"; a Detail group that genuinely holds no content feature is a different answer and does write an empty plan. |
| `swreview remodel plan` | `--package <dir>`, `--document <id>` (repeatable), `--json` | The resilient re-modeler's dry run, and the deliverable feature 004 Phase 0 decides on. Per part document it prints how many content features reach their target group (resolved, unpinned, and on no rebuild list) against how many there are, how many are pinned and by which dependency edge, which of the six groups come out non-contiguous and the interlopers that split them, and the rebuild list with one reason each from the closed eight-value taxonomy of `specs/004-resilient-remodeler/data-model.md` section 1.5. The fraction is printed with its numerator and its denominator and is `null`, never `0.0` and never `1.0`, for a document with no content feature: stage 1's output is a partition with reasons and a bare percentage would read as a score. No SOLIDWORKS, no model: it reads the package, writes nothing at all - no plan file, no session, no report - and constructs no provider, so the same package plans the same way on a machine with no key. The scope gate is reported `unresolved` on every dry run and names each unread signal, because multibody, weldment, sheet metal, mesh and 3D Interconnect are COM readings `remodel.probe_scope` takes from the engineer's open document and a package carries none of them; an unread signal is never a pass. Exit 1 when a part is refused - a scope signal that refuses it, an existing group-named folder holding the wrong members, or a dependency cycle - with every reason named rather than the first, and the numbers printed first, because a refused part is still a part the owner has numbers for. Exit 1 also when the package cannot be read, carries no part document, or `--document` names something it does not carry. |
| `swreview benchmark run` | `--set <set.json>`, `--out <dir>`, `--provider`, `--model`, `--effort` | Reviews every package in the set with answer keys unreadable. |
| `swreview benchmark score <run_dir>` | `--answer-keys <dir>` | Produces `scorecard.json` and `scorecard.md`. |
| `swreview benchmark time <run_dir> <package_id>` | `--baseline M`, `--supervision M`, `--verification M`, `--false-alarms M` | Records timing for net-savings computation. |
| `swreview chat serve` | `--port N` (0 lets the OS pick), `--allow-origin <origin>`, `--run-root <dir>`, `--dev`, `--fail-bridge N` (test hook) | Serves the Task Pane chat backend on 127.0.0.1 and prints `{"port": N, "token": "..."}` as the first and only line on stdout. `python -m swreview.chat` is the same implementation with the same arguments. Wire shapes in `specs/002-task-pane-assistant/contracts/chat-api.md`. |
| `swreview mcp` | `--run-dir <dir>`, `--bridge-pipe <name>`, `--bridge-secret-env <var>` | Serves the read-only general-chat toolset on stdio for an external CLI (`specs/002-task-pane-assistant/contracts/mcp-toolset.md`). This is the only spelling: there is no `-m swreview.mcp`. stdout is the transport, so the command prints nothing of its own; a failure to start is one line on stderr and exit 1. The bridge secret is named by its environment variable, never passed as a value, because a command line is readable by every process on the workstation. |
| `swreview audit-secrets <path>...` | `--bridge-secret-env <var>`, `--detectors\|--no-detectors` (default on), `--json` | Reports any configured secret that reached a file under `path` (FR-015): exit 1 naming the file, the line and the source for every hit, exit 0 when there is none. A file it cannot read is a hit too - unread coverage reported as "none" is the false green the command exists to prevent - and so is having nothing to detect with (no key in the environment, no bridge secret, `--no-detectors`). Detectors flag provider-shaped keys (`sk-...`, `AIza...`), which is what carries the check on the workstation, where the key is DPAPI-protected and reaches only the backend child's environment. Neither the secret nor the line it sat on is ever printed. |

`exceptions accept` and `exceptions list` work unchanged on Resilient Modeling findings:
`accept-rms` is an import path for a file the checker already produces, not a second way to
accept one finding. The rule catalogue the three `rms` commands grade against is
`specs/003-resilient-modeling/contracts/rules.md`.

## `SwReview.Extractor.Console.exe` (C#, `extractor/`)

Out-of-process host around the same extraction library the add-in uses. Requires SOLIDWORKS
2024 installed. **Attach-only by default**: every command attaches to the running instance
and never starts one, because a started session holds a licence and has none of the
engineer's open documents, so it would describe a different model. When the attach fails the
host says which fact differs between SOLIDWORKS and itself (not running / different Windows
session / different integrity level) rather than listing guesses. Exit code 0 success,
1 error; always writes `extract.log` next to the output.

| Command | Arguments | Effect |
|---------|-----------|--------|
| `dump` | `--doc <path>` (or active document), `--config <name>`, `--out <dir>`, `--meshes glb\|stl\|none`, `--faces needed\|all`, `--features tree\|none` (default `tree`), `--equations on\|off` (default `on`), `--profile full\|model-check` (default `full`) | Writes `package.json`, `meshes/`, and appends `gaps` for anything not extractable. `--features tree` adds `features[]` and `--equations on` adds `equations[]` for every resolved part document, once per document, with a gap for anything unreadable and for every lightweight, suppressed or unloaded component. `--profile model-check` runs the document, manifest, mate, feature and equation phases only and skips the hole, fastener, face and body or mesh phases; the profile that produced the package is recorded as `extractor.profile` (optional, default `"full"`, IR 1.2.0), so a consumer can tell a partial extract from a complete one (FR-022). A part opened alone yields one component instance for the part root and that document's feature rows (FR-023). |
| `interference` | `--config`, `--pairs all\|<id,id>...`, `--coincident-as-interference`, `--subassemblies-as-components`, `--fasteners include\|exclude\|only`, `--out <dir>`, `--truncate-after N` (test hook) | Appends `interferences` to `package.json` with per-pair status. |
| `capture` | `--ref <persist_ref>`, `--view iso\|front\|top\|right\|fit`, `--out <dir>` | Zooms to the entity and saves a PNG; appends a `Capture`. |
| `resolve` | `--ref <persist_ref>` | Prints the entity name and type the reference resolves to (round-trip test). |
| `probe rms` | `--doc <part>` | Prints, for one open document, the raw values the feature rules are built on, so the traversal shape is visible before anything is graded: the feature walk (index, depth, type name, name, enclosing folder, sub-feature counts); whether `GetChildren` and `GetParents` returned values per feature; raw sketch statuses; description readability; the equation count and `GlobalVariable` flags; fillet radius readability and the fillet data interface name; the current `GetWhatsWrongCount`; what `IConfiguration.GetRootComponent3(false)` returned for the active configuration and the component and feature counts that follow from it when the document is a part opened alone; and component constrained status, mate entity kinds and mate feature suppression when the document is an assembly. Read-only, through the read-only guard; it grades nothing and writes no package. |
| `suppress-test` | `--doc <part>`, `--plan <suppress-plan.json>`, `--acknowledge-rebuild`, `--out <package dir>`, `--limit <n>` (default 50), `--timeout-seconds <n>` (default 900) | The one mutation path in this product, and engineer-run only: it suppresses each planned Detail feature in turn, rebuilds, records what broke, and restores the tree. It refuses, before touching anything: without `--acknowledge-rebuild`; when `GetSaveFlag` reports unsaved changes (a previous run leaves the document modified - close without saving and reopen); when any feature `IsRolledBack`; when the document's active configuration differs from the plan's; when `GetWhatsWrongCount` is already non-zero (the message names the pre-existing errors); and when the live feature walk differs from the package's `features[]` for this document in count, order, type names, names, depth or suppression state, or any planned feature fails `IsSamePersistentID` (the message says: dump again). Per feature: skip if already suppressed; `SetSuppression2` in this configuration; verify applied (else `not_applied`, no rebuild); `ForceRebuild3(false)`; record `GetWhatsWrongCount` and up to 20 `GetWhatsWrong` messages; restore the whole tree from the snapshot and verify. `--limit` and `--timeout-seconds` stop it with `truncated` rows. On any exception the restore still runs, unrestored features are named on stderr and in `suppress-test.log`, and the exit code is non-zero. It runs under `SuppressTestGuard` with a recording gate observer whose distinct member names are written to `suppress-test.log`, appends `rms_suppress_test` through `PackageAppender`, **never saves**, and ends by printing that the document is modified in memory and must be closed without saving. Not available from the add-in, the bridge or the MCP toolset. |
| `serve` | `--pipe <name>` | Runs the bridge for the Python `--bridge` tools: one JSON request per line on a named pipe, one COM STA worker thread. |
| *(all of the above)* | `--allow-start` | Permits starting a SOLIDWORKS session when none is running. Off by default; for unattended scripts only. |

Add-in: the same library is loaded in-process by `SwReview.AddIn` and exposes Task Pane
buttons **Dump IR**, **Interference**, and **Capture selection** that call the same entry
points with the active document. The Model check tab calls the same `dump` entry point with
`--profile model-check` and then the reviewer's `run_rms_check`; it adds no command here,
and `suppress-test` stays out of the pane because the one mutation path is deliberately a
command an engineer types.
