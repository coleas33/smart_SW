# Tasks: LLM Efficiency, Speed, and Token Usage

**Input**: Design documents from `/specs/005-llm-efficiency/` (spec.md, plan.md, data-model.md, contracts/, quickstart.md) and `docs/llm-efficiency-options.md`.

**Prerequisites**: features 001, 002 and 003 complete. Feature 004 is independent of this one and neither blocks the other.

**The rule this whole list obeys**: instrument first, then one lever at a time behind a flag, default off, adopted only on measured evidence with no quality regression. No task below turns a lever on by default. Every lever ends in two tasks, an A/B run and an adoption decision, and the decision is the owner's, taken against a recorded number. A lever that fails its gate stays off and its ledger row stays in the ledger.

**Tests**: REQUIRED. Tests precede implementation in every phase. Feature 001, 002 and 003 golden baselines must stay byte-identical, with one authorized exception: `report.md` grows a `## Tokens` section rendered **only** when `session.usage is not None`, so a golden session written without usage is unchanged byte for byte. Any golden diff beyond that is a defect in this feature, not a baseline to refresh.

**Organization**: Phase 1 instrumentation and the baseline (no flags, nothing optional), including two standalone correctness fixes and the benchmark set that gates every later decision. Phase 2 the A/B harness and the results ledger. Phase 3 Tier 1 levers (3-OpenAI, 2, 4, 3-Gemini). Phase 4 Tier 2 levers (6, 5, 7). Phase 5 Tier 3 levers (9, 10a, 11a) on the workstation, plus lever 12 as standing practice. Levers 8, 10b and 11b are out of scope and are argued out in the spec.

## Format: `[ID] [P?] [W?] [K?] [Lever] Description`

- `[P]` the task can run in parallel with the other `[P]` tasks in its group (different files, no shared edit)
- `[W]` needs the pilot workstation: SOLIDWORKS 2024 SP5, the add-in registered, a real document open
- `[K]` needs a live provider key and spends real money; every such task records the commit sha, the flag values, the provider, the model, the effort and the start time
- `[Lever]` the lever the task belongs to (`[L2]`, `[L3]`, `[L4]`, `[L5]`, `[L6]`, `[L7]`, `[L9]`, `[L10]`, `[L11]`, `[L12]`); Phase 1 and Phase 2 tasks carry no lever tag because they belong to all of them

## Path Conventions

- Python: `reviewer/src/swreview/`, tests in `reviewer/tests/{unit,integration,golden,live,perf}/`
- C#: `extractor/SwReview.Extractor/`, `extractor/SwReview.Extractor.Console/`, `extractor/SwReview.AddIn/`, tests in `extractor/SwReview.Extractor.Tests/`
- Contracts: `specs/001-agentic-design-review/contracts/`, `specs/002-task-pane-assistant/contracts/`
- Measured results: `specs/005-llm-efficiency/probe-log.md` (probe answers) and `docs/llm-efficiency-options.md` (the generated ledger)

## Verification legend, carried into every task

A claim about an SDK field or behavior is **VERIFIED** only when it was read in the package installed under `reviewer/.venv/Lib/site-packages` (`openai` 3.13.0, `google-genai` 2.23.0) at a named file and line, and **UNVERIFIED** when it needs a live call, a SOLIDWORKS seat or a timed run. VERIFIED never means an API was observed behaving a certain way. Every UNVERIFIED claim that gates a decision has a probe task below, and no task may promote a claim from UNVERIFIED to VERIFIED without that probe's recorded output in `probe-log.md`.
