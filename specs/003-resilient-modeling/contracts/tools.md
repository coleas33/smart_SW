# Tools Added by Feature 003

All follow feature 001 `contracts/agent-tools.md` rules (ids and refs only, recorded steps,
error results never raise). Schemas are generated by `providers/schema.py`. Each registering
task also adds the tool's row to feature 001 `contracts/agent-tools.md`, which
`test_provider_schema.py` checks against the registry.

## Query tools (`tools/rms_query.py`, registered in `query_tools()`; review, general chat, MCP)

| Tool | Arguments | Returns |
|------|-----------|---------|
| `list_features` | `document_id: str`, `folder: str \| null` (group name or folder feature id), `include_suppressed: bool = true` | ordered `{id, name, type_name, class, group, folder_id, depth, suppressed, description}` |
| `get_feature` | `feature_id: str` | the full `Feature` plus derived `class`, `group`, `is_folder`, `is_end_tag`, and `child_ids`/`parent_ids`/`consumer_ids` resolved to names |
| `list_equations` | `document_id: str` | the document's `Equation` list |

Registering them in `query_tools()` puts them in the MCP server automatically
(`MCP_TOOL_FUNCTIONS` spreads `query_tools()`). The same task updates, together and with
tests, `QUERY_TOOLS`/`OFFLINE_TOOLS` and `TOOL_MODULES` in `test_mcp_server.py`, feature 002
`contracts/mcp-toolset.md`, `CliProfileWriter.EnabledTools`, feature 002
`contracts/cli-profiles.md` (`enabled_tools`), and `CliProfileWriterTests`; a new test asserts
that the function names of `MCP_TOOL_FUNCTIONS + MCP_BRIDGE_TOOL_FUNCTIONS` equal the
`enabled_tools` list parsed from `cli-profiles.md`, so a tool added on one side can never be
withheld on the other by accident (FR-019).

## Check tools (`tools/rms_checks.py`, registered in `check_tools()`; review only)

| Tool | Arguments | Produces |
|------|-----------|----------|
| `check_rms_part` | `document_id: str \| null` (null = every part document, including unresolved ones) | one `Finding` per failing, warning, or waived result per part; aggregated coverage per rule per bucket; the `modeling.resilience` summary item; the `rms.types.unknown` item when needed |
| `check_rms_assembly` | none | assembly-scope findings and aggregated coverage for the root assembly document; the `rms.assembly.subassemblies` item naming the subassembly documents |
| `check_rms_equations` | `document_id: str \| null` (null = every part document) | equation-scope findings and aggregated coverage |

Whichever of the three runs first in a session also writes the four data-gap rules to
`unresolved` and the six out-of-scope rules to `out_of_scope`; later calls skip items the
session already holds. Each call re-evaluates its scope in full and replaces its own earlier
aggregated items through `ToolContext.replace_coverage(check, bucket, item)` (added by this
feature; it removes the session's items with that check in that bucket and appends the new
one through the same coverage event), so running a tool twice does not duplicate coverage.

Exceptions: for every `fail` outcome the tool asks `ExceptionStore.match(package,
component_ids, configuration, check=rule_id)`; `active` → `waived`, `needs_review` → the
finding stands with `needs re-review: <id>` in observed. `warn` outcomes never consult
exceptions.

## Checklist item

```yaml
- id: modeling.resilience
  title: Resilient Modeling Strategy
  check_prefix: rms.
  description: >
    Part feature trees follow the six-group discipline with one-directional references,
    fully defined sketches and described features; the root assembly mates to reference
    geometry with a fixed or fully constrained first component and shallow chains; parts
    carry global variables. Run check_rms_part, check_rms_assembly and check_rms_equations.
    Drawing and judgement-only rules are recorded as out of scope with the reason.
```

## No tool is added by User Story 6

The Model check tab registers no tool: it calls `POST /checks/rms`, which calls
`checks/rms/run.py::run_rms_check`, which dispatches `check_rms_part` (and, when the scope
asks for them, `check_rms_equations` and `check_rms_assembly`) through the same
`ToolRegistry` with a session sink, so the tab's findings carry the same recorded steps as a
review's (FR-024, FR-031). The MCP function list and the terminal profile's `enabled_tools`
therefore do not move for User Story 6, and `test_mcp_server.py`, `ToolListingCheckTests` and
`CliProfileWriterTests` must pass unedited; if any of them needs an edit, something has been
registered that should not have been.
