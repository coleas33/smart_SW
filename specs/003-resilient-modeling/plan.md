# Implementation Plan: Resilient Modeling Checks

**Branch**: `003-resilient-modeling` | **Date**: 2026-09-16 (revision 4, User Story 6 added) | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-resilient-modeling/spec.md`

## Summary

Add a read-only feature-tree and equation dump to the C# extractor (IR 1.1.0), a Python rule
family that evaluates the Resilient Modeling Strategy's part, assembly, and equation rules
as findings and aggregated coverage, tools and a checklist item so the review loop uses
them, a CLI check, exceptions through the existing store, a reviewer-written suppress-test
plan, and an engineer-run console command for the one rule that must mutate a document.
Rule semantics come from the source checker, reused with permission; the deliberate
deviations are recorded in research R2. User Story 6 adds a fourth task-pane tab, **Model
check**, that extracts the open part with a reduced dump profile and grades it against the
same rules with no language model, no API key and no network, behind one shared evaluation
entry point that the command line and the backend route both call; this story is also the
prerequisite for feature 004, whose subject is always a part opened alone.

**Target Platform**: as features 001 and 002.

**Project Type**: extends both trees.

**Performance Goals**: feature and equation dump adds under 20 s on a 200-component assembly
(one tree walk per part document, not per instance), measured in T062; rule evaluation under

**Constraints**: read-only dump; the only mutation path is the console `suppress-test`

**Scale/Scope**: assemblies to 500 components, parts to 1000 features.

## Phase 0 and Phase 1

Research in [research.md](research.md) (R1 to R10). Design in [data-model.md](data-model.md)
and [contracts/](contracts/). Key points tasks must honor:

1. **Folders, end-tags, sticky groups, subfolders** are decided once, in
   `checks/rms/groups.py`, from `folder_type` and `end_tag_suffix` in the table, with the
   normative text in `contracts/rules.md`; the C# indexer records index, depth, and enclosing
   folder from sub-feature structure and knows no names. Both traversal shapes are supported.
2. **Unknown and ambiguous types** flow through `RmsTypeTable.classify` returning exactly one
   value; every class-dependent rule consults the class through one helper that yields
   `unresolved` for `unknown` and, unless the rule reads material, for `ambiguous`; rules that
   need no class treat unknown types as content.
3. **One rule registry** (`checks/rms/registry.py`) holds id, scope, severity, statement, and
   either a function or a coverage reason; the checklist, tools, CLI, and docs read the
   registry, never a second list. 34 ids.
4. **One finding path**: `RuleResult` wraps `CheckResult`, one per outcome; `report.py` calls
   `tools/recording.py` (with the new `tool_result_ids`) for findings and writes aggregated
   coverage through `replace_coverage`, the summary item, the unknown-types item, and the
   once-per-session data-gap and out-of-scope items.
5. **One silence mechanism**: `ExceptionStore` with `fingerprint_kind`; no waiver file in the
   package; the checker's flat file is an import; `match` requires `check` everywhere.
6. **Suppress-test** runs from a reviewer-written plan, is the only writer of
   `rms_suppress_test`, through `PackageAppender`; the Python rule only reads. The guard seam
   is the only change to `SwGate`.
7. **A part opened alone must dump its features.** `ComponentTreeDumper.Traverse` builds the
   tree from `IConfiguration.GetRootComponent3(false)` (verified present on the 2024 SP5
   interop), which is expected to return null on a part opened alone (unverified on 2024,
   PROBE-15). Today that leaves the component list empty, `FeatureDumper` iterates nothing,
   and every part rule comes back unresolved. The dumper synthesizes the part root from the
   document itself. This is the one change without which the tab, and feature 004, have no
   input at all.
8. **One reduced profile, recorded in the package.** `DumpProfile { Full, ModelCheck }` gates
   four phases in `PackageWriter.Build`; the saving is most of a dump's cost, because the full
   dump also tessellates every body, writes GLB files and reads face geometry. The profile is
   recorded as `ExtractorInfo.profile`, optional with default `"full"`, which is why the IR
   bump is minor (1.1.0 to 1.2.0) and 1.1.0 packages still load.
9. **One evaluation entry point.** `checks/rms/run.py::run_rms_check(package_dir, *, scope,
   document_id)` is the single no-language-model path; `swreview check rms` (T029, refactored)
   and `POST /checks/rms` are its two callers. Three options were weighed: a backend route, a
   `swreview check rms --json` subprocess launched by the add-in, and one shared core with two
   callers. The shared core is taken. The subprocess is rejected: `uv run` re-resolves the
   environment and then imports `swreview`, pydantic, typer and PyYAML, which is 1 to 3 seconds
   of cold start on the one path where the work itself is tens of milliseconds, and it would add
   a second transport exercised only when something is already broken.
10. **One grade model.** `checks/rms/grade.py::RmsGrade` lives in feature 003 because the tab
    needs it first and feature 004 needs the same number before and after. Headline is counts
    per bucket; the fraction `checked / (checked + failed + warned)` is secondary; the
    unresolved rule ids are always named beside it. No letter: a letter is exactly the
    confident-but-unsupported artefact Principle I exists to prevent.
11. **Exceptions are carried forward at run-folder creation**, in Python inside `run_rms_check`
    so the command line gets it too: the newest `exceptions.json` under the run root whose
    package carries the same `design_id` is copied byte-identically into the new folder before
    the rules run. The run folder stays self-contained and replayable, which is the point of its
    current design. A per-design store at `<run_root>/exceptions/<design_id>.json` is the
    cleaner greenfield answer and is on the backlog; it is not taken now because it moves where
    feature 001's exceptions live and touches `runner.py`, `cli.py`, `golden_interference.py`
    and the goldens.
12. **Four things feature 004 consumes rather than re-creates**, and each must therefore be
    built here, not copied there: the part-root node and `DumpProfile.ModelCheck` (T064),
    `run_rms_check` and `grade.py` (T067, T069), `PaneActions` (T075), `FeatureSelection`
    (T079), and `web/shared/dom.js` (T080). This list is the DRY contract between the two
    features and belongs in the plan so that a later change to any of them is known to have two
    consumers.

## The step strip and the partial-evidence trap

The step strip above the tabs (open document, extract evidence, then Review, Ask, Model check
or Remodel) does not exist in the repository yet; this is how User Story 6 must meet it. Steps
1 and 3 are trivial. Step 2 is a trap: a model-check package has no faces, no holes, no
fasteners and no meshes, so a strip that lets the engineer press Review next would have the
agent review a model it cannot see, and every geometric check would come back unresolved. That
reads as a bad model rather than as a missing extract, which is a silent quality collapse.

The fix is the one already listed as key point 8, used three ways: the package records its
profile; the evidence step reads "Evidence: model check only (features and equations)" and
offers **Extract full evidence** before Review; `POST /sessions` records a coverage item naming
the missing phases when it is handed a `model_check` package; and `swreview check rms` refuses
a package whose features array is empty instead of reporting 34 unresolved rules.

## Risks and mitigations

| Risk | Mitigation |
|------|------------|
| 2024 returns nothing from `GetChildren` or `GetParents` | Dumper records null plus gap; rules unresolved; probe shows which |
| Folder contents come back flat on 2024 rather than nested | Indexer records structure as seen; group assigner handles both shapes, including derived subfolders; tested over both fake sequences |
| Weldment, sheet-metal, derived-part type names unknown to the tables | Unknown types are content for grouping and description and unresolved for class rules; probe lists them; T062 adds them to `tolerated_loose` or a class |
| `ICE` on 2024 | Marked ambiguous; material for the group-content rule, unresolved for holes_last |
| Suppress-test leaves a model modified | Whole-tree snapshot, restore after every feature, verification, breaker reset before restore, unrestored features named, never saves, refuses unsaved and rolled-back documents; the document is reported modified in memory |
| Suppress-test rows applied to the wrong feature or the wrong state | Plan carries persistent refs; the command refuses a tree that differs from the package and binds each row by `IsSamePersistentID`; a later dump drops the run |
| Pre-existing rebuild errors fail every feature | Baseline read first; non-zero baseline refuses the run |
| Coverage volume at 500 components | Aggregated per rule per bucket, replaced on re-run |
| Rule tables drift from the source | `calibrated_version` and the provenance comment in the single shipped YAML; deviations listed in research R2; T062 re-verifies |
| A query tool exposed by MCP but withheld by the terminal profile | One test asserts the MCP function names and the profile's `enabled_tools` are the same list |
| An RMS exception silences an interference finding with the same bindings | `match` requires `check` for every caller |
