**Tests**: REQUIRED. Every implementation task is preceded by its own test task, and the test must fail before the implementation exists. Feature 001, 002 and 003 golden baselines stay byte-identical; the feature 001 finding contract is unchanged; `ReadOnlyGuard` is not widened by any task in this feature.

**API convention**: every interop member named below is marked `(VERIFIED)` when the member exists with that signature, or the enum constant has that integer value, on SOLIDWORKS 2024 SP5 / `SolidWorks.Interop.sldworks` 32.5.0.48, and `(UNVERIFIED)` when only its behavior is in question. VERIFIED never means the call behaves; that is what Phase 2 is for.

**Scope**: stage 1 (reorganize) only. Stage 2 (rebuild) does not ship in this increment; it is re-specified after stage 1 runs on real parts. The `GateResult` type is tri-state (`pass` / `fail` / `unresolved`) from day one so stage 2 adds a tier rather than changing a type. Parts only. The reviewer and the Model check tab stay read-only and no task below changes that.

**Organization**: phases 0 to 9. Phases 0, 2, 3, 4 and 9 are setup, probe, foundational and polish and carry no story tag, exactly as feature 003 does.

- **US1** (P1) Reorganize a part into the six groups with the geometry proven unchanged. Phases 5 (T074 to T089) and 6.

- **US3** (P3) Descriptions and global variables proposed by the model, applied by the executor. Phase 7.
- **US4** (P4) The run-to-completion report. Phase 5 (T090 to T093) and Phase 8.

## Notes

- The re-modeler works on a **copy it creates in the run folder** and never saves over an existing file. Nothing in stage 1 uses `SaveAs*`; `Save3` takes no filename (VERIFIED) and the copy is opened at its own path, so the source is unreachable rather than merely un-targeted. That property is structural, and every test that pins it (T044, T048, T050, T086) is load-bearing.
- **No `remodel.*` bridge command and no model-facing tool names a document.** Do not add a document parameter "for validation"; the absence is the guarantee.
- The allowlist is closed and interface-qualified. Adding a member to it is a spec change, not an implementation detail. Stage 2 gets a **second additive allowlist**, reviewed on its own.
- `IModelDoc2.EditUndo2` (VERIFIED, returns void) is never used at any tier, and `StartRecordingUndoObject` and `FinishRecordingUndoObject2` are not allowlisted, because an unused allowlist entry is exactly the accidental widening the allowlist exists to prevent.
- The run goes **to completion** and then presents the change list, the before-and-after grade and the geometry comparison. There is no approve-each-change mode.
- An unknown feature type, an unreadable dependency graph, an unreadable fillet radius and an unresolvable persist ref are all `unresolved`, never "movable" and never "pass".
- Success is measured on the **quality of the partition**, not on the size of the reorganized fraction. A run that moves 3 of 200 features is a correct run that says the part needs rebuilding.
- Stage 2 (rebuild) is out of scope for this increment and is re-specified after stage 1 has run on real parts. The tri-state `GateResult` and the optional residual argument exist so that stage 2 adds a tier without a type change.
