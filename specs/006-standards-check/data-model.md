# Data Model: Standards Check

**Feature**: `006-standards-check` | **Date**: 2026-09-17 | **Spec**: [spec.md](spec.md)

Extends the feature 001 IR to `schema_version` **1.4.0** (minor: two new optional arrays,
**ten** new optional fields on existing models plus one new optional field on the PDF ingest's
`DrawingSheet`, one widened enum (`ExtractorInfo.profile`), new gap entity kinds, two new dump
phases). **`contracts/ir-additions.md` section 1 is where that count is stated and where the
field rows live**; every other file cites it rather than repeating the number. Conventions from feature 001 apply: lengths are
`Quantity` with a unit, persistent references are base64 with a scope document, absence is
`null` plus a `Gap`. The feature 001 review-session schema (`Finding`, `CoverageItem`) is
**not** changed.

**The additivity rule, in one place** (FR-023). Every field and every model this feature adds
is optional, carries a default, is **omitted when null** (or when empty, for the two new
arrays) and is absent from the `required` set in both serializers. The minor version is
bumped once, in `reviewer/src/swreview/ir/models.py` and
`extractor/SwReview.Extractor/Ir/EvidencePackage.cs` together, and
`specs/001-agentic-design-review/contracts/ir.schema.json` is regenerated by
`python -m swreview.ir.schema --write`. A 1.3.0 package loads in a 1.4.0 build; both
serializers still forbid unknown members, so a 1.4.0 package is readable only by 1.4.0 or
later builds. **The feature 001, 002 and 003 golden fixtures are byte-identical** (SC-004):
they are static files, and every new field is omitted when null, so a package that carries
none of this feature's evidence serializes exactly as it did.

The one visible consequence is stated rather than discovered: `extractor.phases` gains two
rows, `cutlist` and `drawing`, `skipped` for any profile that does not run them. Golden files
on disk do not move; the tests that pin the **full phase list** are edited in the task that
adds the phases.

## 1. The standards profile (not IR; not in this repository)

`checks/standards/profile.py` owns this schema and is the only place it is expressed
(FR-002). `contracts/profile.md` is the normative document; this is the model.

| Field | Type | Rules |
|---|---|---|
| `version` | int | `1`. A profile whose version this build does not know refuses the run naming both versions |
| `vault_root` | str | An absolute directory. Library prefixes written relative are resolved against it before matching; an absolute prefix is matched as written. A vault root that does not exist on this machine is **accepted** - a package can come from another machine and the prefix match is textual |
| `library.skip_prefixes` | list[str] | Matching **part** documents get the four part checks and the data-card check as skipped coverage naming the matched prefix. Assembly documents under these prefixes are graded normally |
| `library.sketch_exempt_prefixes` | list[str] | Matching part documents get `standards.part.sketches_fully_defined` as skipped coverage. Affects no other check |
| `library.one_mate_prefixes` | list[str] | A matching under-constrained component needs at least one unsuppressed mate |
| `library.two_mate_prefixes` | list[str] | A matching under-constrained component needs at least two unsuppressed mates |
| `data_card.properties` | list[str] | Property names that must be present and non-blank on a document whose file name matches the pattern |
| `part_number.pattern` | str | `#` = one digit, `?` = one character, every other character literal; matched case-insensitively as a **whole-string** match against the file name **including its extension** |
| `revision.property` | str | The custom property holding the revision on the drawing and on its referenced models |
| `revision.initial` | str | What a revision table holding only its header row means |
| `revision.header_text` | str | The first cell's text that identifies the header row |
| `revision.cell.row_from_end` | int >= 0 | `0` is the last row, `1` the one above it |
| `revision.cell.column` | int >= 0 | Column index |
| `material.configuration` | str | The configuration whose material `standards.part.material_assigned` compares |
| `export_control.phrase` | str | Presence anywhere in a drawing's note text is the defect; matched case-insensitively as a substring |

**Empty is valid, and never a pass - but what "empty" means depends on what the setting does**
(`contracts/rules.md` is normative). A setting that **selects what to check**
(`data_card.properties`, `part_number.pattern`, `revision.property`, `export_control.phrase`)
leaves nothing to test when it is empty, so its check is **skipped** coverage naming the empty
setting and the skipped count travels on the headline. A list that **exempts or reclassifies**
(the four `library.*` lists) exempts and reclassifies nothing when it is empty, so its checks
**run on every document they apply to**. The first half stops an unconfigured profile silently
passing a document; the second stops it silently grading nothing. **There is no fallback**: a
missing, unreadable or schema-invalid profile refuses the run, because a default value would
grade a document against the wrong standard in silence.

**`ProfileIdentity`** is what leaves the reasoning side: `{path: str, sha256: str}`. It is
what the check record, the session, the report and every finding's `coverage_limits` carry.
**No profile value appears in any of them** (FR-034).

### 2.4 Gap `entity_kind` values added

`assembly_exploded`, `rebuild_error_count`, `mass_override`, `component_transparency`,
`component_visibility`, `component_pattern`, `mate_entity_reference`, `sketch_text`,
`cut_list_body_count`, `cut_list_exclusion`, `cut_list_folder`, `drawing_sheet`,
`drawing_sheet_views`, `drawing_view`, `drawing_referenced_document`, `dimension_override`,
`dimension_unit`, `annotation_identity`, `annotation_dangling`, `note_text`,
`revision_table_read`. Each names one `entity_id` where one exists. Every kind in this list has
a producing condition in `contracts/ir-additions.md`; `cut_list_folder` is emitted when a
body-folder's `GetTypeName2` or `GetSpecificFeature2` could not be read, which PROBE-8 makes
likely enough to name. There is deliberately **no** `drawing_persist_ref` kind: a missing
persistent reference is a **null `persist_ref`**, which is the statement FR-026 requires, not a
gap.

The existing standing gap `"The native extractor does not read drawing sheets; they come from
the PDF ingest."` becomes **conditional**: it is emitted only when the drawing phase did not
run, and it then names the profile that skipped it (FR-024).

### 2.5 Dump phases and profile

`PackageWriter.PhaseOrder` becomes
`document, manifest, mate, feature, equation, cutlist, drawing, hole, fastener, face, body`.

| Profile | Phases run |
|---|---|
| `full` | document, manifest, mate, feature, equation, cutlist, hole, fastener, face, body - ten; plus `drawing` **only** for a drawing root, recorded `skipped` otherwise |
| `model_check` | document, manifest, mate, feature, equation |
| `standards` | document, manifest, mate, feature, equation, **cutlist**, and **drawing** when the root document is a drawing |

`standards` extends `model_check` and still skips hole, fastener, face and body - the four
phases that tessellate, write meshes and read face geometry, which is most of a dump's cost
and none of which any standards check reads. `full` also runs `cutlist`, and `drawing` for a
drawing root, so **a full extract is never less complete than a standards one** (FR-027).

A consumer decides whether the standards evidence is present from the **phase rows**, not from
the profile name: `swreview check standards` refuses a package whose `cutlist` row (or, for a
drawing, `drawing` row) is `skipped`, naming the profile that produced it and the phases that
are missing, and accepts any package that actually ran them (FR-043).

### Severity, outcome and finding mapping (FR-030)

| Outcome | Result |
|---|---|
| `fail` on an **error** check | `Finding` status `demonstrated`, severity `high` for the four data-integrity checks (`mate_references`, `rebuild_errors` both, `dimensions_not_overridden`), `medium` otherwise |
| `fail` on a **warning** check | `Finding` status `suspected`, severity `low` |
| `waived` | `Finding` status `checked_within_scope`, `coverage_limits` carries `exception:<id>: <note>`, `exception_id` set |
| `pass` | aggregated `CoverageItem` in `checked` |
| `skip` | aggregated `CoverageItem` in `skipped` |
| `unresolved` | aggregated `CoverageItem` in `unresolved` |

**Out of scope is not an outcome.** `RuleOutcome` has six values (`pass`, `fail`, `warn`,
`skip`, `unresolved`, `waived`) and this feature does not add a seventh, because adding one
would change feature 003's result model and its tests, which RK-7 requires to pass unedited.
An out-of-scope row is therefore **not a `RuleResult` at all**: after the results are
aggregated, `checks/standards/report.py` walks (every rule) x (every graded document) and
writes one `out_of_scope` `CoverageItem` for each pair whose rule scope does not match the
document's kind, naming the kind. `checks/standards/report.py` owns that loop; nothing in
`checks/rules/` knows about it, and the `StandardsRule` invariant (severity xor coverage
reason) is untouched.

### Finding fields (no change to the feature 001 contract)

1. `Finding.check` is the check id. `Finding.component_ids` are the ids of every
   `ComponentInstance` that reaches the graded document, in package order. For a **drawing**
   document there are none, and the finding names the document in `observed` and in the new
   `Subject` array instead - which is also why the exception record gains `document_id`.
2. Each failing subject is one `Finding.inputs` entry, formatted
   `<kind> <id> <name> persist_ref=<ref|none> scope=<document_id>`, and is named in
   `observed`. The same subjects appear as structured `Subject` records **beside** the finding
   in the route's response, keyed by finding id.
3. `Finding.requirement` is the check's statement; `recommended_action` is the check's
   recommended change; `tool_result_ids` names the recording step, which exists because the
   run dispatches through `ToolRegistry` with a `SessionSink`.
4. `coverage_limits` always carries the profile identity (`profile:<path> sha256:<hash>`) and,
   where they apply: `configuration <name>`, `unresolved instances: <ids>`,
   `counts as the document stood; nothing was rebuilt`, and
   `exception:<id>: <note>` when waived.

### Coverage aggregation (FR-033)

One `CoverageItem` per check per bucket per run: `check` is the check id,
`scope.document_ids` the documents in that bucket, `scope.configuration` the run's
configuration, `reason` `<n> document(s)` followed by the per-document reasons
(`doc:3: no cut-list items; doc:5: library prefix _library/bonding/`). Written through
`ToolContext.replace_coverage`, so a re-run replaces rather than duplicates.

Plus one **`standards.release` summary item** carrying the verdict state and the counts per
bucket. It is the family's `summary_check`, the standards counterpart of feature 003's
`modeling.resilience`: a coverage item only, never a check, **excluded from the sixteen-row
`checks[]` array** and from every waiver (`contracts/rules.md`). "No seventeenth result" means
no seventeenth **check** result.

**All sixteen checks appear on every run.** Where a single line must stand for a check, the
worst bucket it reached decides it, in the order **unresolved, failed, warned, skipped,
checked, out of scope**, so no summary line claims coverage that is partly unknown.

**`worst_bucket` is a presentation value, not a session bucket.** The review session has
exactly five coverage buckets - `checked`, `skipped`, `unresolved`, `failed`, `out_of_scope` -
and this feature does **not** change that schema. `failed` and `warned` in a check's rendered
bucket list are derived by `checks/standards/report.py` from the **findings** for that (check,
document) pair - an `error`-severity finding renders as `failed`, a `warning`-severity one as
`warned` - and are never read from `session.coverage`, which has no `warned` bucket to read.

## 4. The check record and the run folder

`<run_root>/<yyyyMMdd-HHmmss>-<doc>-standards/`:

```
package.json      the Standards-profile dump; extractor.profile == "standards"
exceptions.json   carried forward from the newest same-design run, before the checks run
session.json      the recorded tool steps, so tool_result_ids name steps that exist
report.md         the check-by-check result, headed by the verdict and the no-rebuild sentence
check.json        what the session does not hold (below)
```

`check.json` gains **`family`** (FR-034):

| Field | Type | Rules |
|---|---|---|
| `family` | `"rms" \| "standards"` | **Optional with the default `"rms"`**, so every model check record already written still reads. `GET /checks/{check_id}` dispatches on it and neither family answers for the other |
| `session_id` | str | Ties the record to the session in the folder; a folder whose session is no longer the recorded one is no longer this check |
| `documents` | list[str] | Every document graded, in traversal order |
| `document_kinds` | dict[str, str] | Kind per graded document, so a read need not re-open the package |
| `document_reached_by` | dict[str, str] | How each graded document was reached (`root`, `component_tree`, `drawing_reference`), so `GET` answers `documents_graded[].reached_by` without re-walking the package (added 2026-09-17 with T074) |
| `profile` | `{path, sha256}` | **Identity only.** No profile value is written here, into the session, into the report or into any message to the page |
| `verdict` | `ReleaseVerdict` | |
| `subjects` | dict[finding id, list[`Subject`]] | Beside the findings, never inside the `Finding` |
| `exceptions_carried_forward` | `{from_run, count, reason}` | Reported in every case, including when nothing was carried |
| `unavailable_checks` | list[`{check, reason}`] | A check this build does not run yet, reported rather than silently absent |

The folder is **registered as the pane's latest run**, exactly as a model check folder is, so
`entity.show` resolves document ids through the package in it and the Ask tab opens in the
same place.

**The newest-run scan is new work, not an existing mechanism being filtered.** Today
`ModelCheckHost.LatestCheck` is in-process state: it is set by `TrackCheck` when a check runs
and nulled in `Dispose`, and nothing in the add-in enumerates the run root at all. Reading a
check back after a restart (FR-034, SC-009) therefore needs a scan that does not exist, and it
is **added** by this feature: `RunFolders.NewestCheckFolder(runRoot, suffix)`, called on `init`
by `StandardsHost` with `-standards` and by `ModelCheckHost` with `-check`. The `-standards`
suffix is what lets that one scan answer for each host **from the folder names alone**, with no
`check.json` read per sibling folder; the `family` field in `check.json` is how the backend
answers a read by an id it was handed. Two mechanisms, two questions.

## 5. Exceptions (waivers)

`ReviewException` gains one field, and three functions in `exceptions.py` gain a
document-scoped path. The field alone is not enough, and the rest is named here rather than
discovered:

| Field | Type | Rules |
|---|---|---|
| `document_id` | `str \| null` | **Optional with the default `null`**, so every existing record loads. Set for `standards.*` exceptions. It exists because a **drawing** finding has no component instances, and an exception with no bindings at all would be the blanket exclusion the constitution prohibits |

**The three changes to `exceptions.py` that make a drawing waiver possible**, each additive and
each with a regression that the existing geometry and feature-tree paths are unchanged:

1. `fingerprint(...)` raises today when `component_ids` is empty (`a <kind> fingerprint needs
   at least one component`). The `"standards"` kind gains a **document-scoped** path that
   hashes the check's inputs for a `document_id` and needs no component.
2. `accept(...)` builds its fingerprint from `finding_like.component_ids`. It gains a
   document-bound target: when the finding carries no instances, the exception is bound by
   `document_id` and its `bindings` are empty by construction rather than by accident.
3. `match(...)` compares `(check, configuration, bindings)` only. Two drawings both yield empty
   bindings, so **one drawing's waiver would answer for every other drawing** - exactly what
   FR-041, RK-11 and SC-008 forbid. It therefore takes and compares `document_id`, so an
   empty-binding exception is keyed by the document it was accepted on. A regression asserts an
   existing geometry or feature-tree exception matches exactly as it did.

`fingerprint_kind` gains `"standards"`. The standards fingerprint hashes **every input the
check read for that document**, in a stable order: for an assembly, the instance ids with their
`is_fixed`, `constrained_status_raw`, `visibility_raw`, `transparency_raw`,
`has_appearance_override`, `is_pattern_instance` and unsuppressed mate count, plus each mate's
entity resolution statuses; for a part, the feature rows (`index`, `type_name`, `name`,
`error_code`, `sketch.raw_status`, `sketch.text_segment_count`), the material and its
configuration, the mass-override flag and the cut-list items with their exclusion flags; for a
drawing, the sheets, views, dimension override flags, annotation dangling flags, revision-table
cells and note texts; and for the data-card check, the profile property names and their three
states. So a **newly appearing subject re-opens the finding for re-review** rather than being
silenced (SC-008), and a fix elsewhere in the same check also re-opens it - which is the
conservative direction.

`ExceptionStore.match` already requires `check`; the standards family passes its check id, so
a standards exception can never answer an interference or RMS query that happens to share
bindings. That covers **cross-family**; `document_id` above is what covers **cross-document**,
which the check alone does not. Only **error**-severity checks are acceptable; a waiver naming
`standards.drawing.revision_matches` or `standards.drawing.no_itar_statement` is reported
`invalid (warning check)` and changes nothing, and the Accept control is **absent** for them
rather than disabled.

## 6. State the tab reads back

Nothing is persisted except through the run folder. After a restart the page sends `ready`,
receives `init` carrying `latest_check` (the newest **`-standards`** folder under the run
root, found by `RunFolders.NewestCheckFolder` from the folder names, with its id and
timestamp), and calls `GET /checks/{check_id}` itself **without the engineer pressing
Standards** - pressing Standards runs a new check, so it is not how a previous one is read
back. That read is a
**read**: `read_standards_check` rebuilds the result from `session.json` (the findings, the
coverage and therefore the counts) and `check.json` (the verdict, the documents, the subjects,
the profile identity and what the carry-forward did) and evaluates nothing. Answering it by
re-running the checks would write a new session id and a new `report.md` on every page
refresh, over the file an engineer's recorded disposition lives in.

What the page therefore holds after a restart, with no SOLIDWORKS interaction at all: the
verdict and its counts, the sixteen check rows with their buckets and reasons, every finding
with its subjects and their `showable` flag, the exception state of each waived finding, the
profile path and hash, and the run folder's id for `report.open` and `folder.open`.
