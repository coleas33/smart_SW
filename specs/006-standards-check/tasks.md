# Tasks: Standards Check

**Input**: Design documents from `/specs/006-standards-check/` (`spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`)

**Tests**: REQUIRED, and **strictly test-first**: every implementation task below is preceded by the test task that must be written and must fail first. ## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on another unfinished task)
- **[Story]**: `US1` to `US4`; Setup, Foundational and Polish tasks carry no story tag
- **[W]**: needs the pilot workstation and a SOLIDWORKS seat
- **[K]**: needs an API key — **no task in this feature carries it**, because no language model is involved on any path (FR-045)

## Notes

- **The profile is the only place a company value enters a run.** No fallback exists, by construction; a missing, unreadable or schema-invalid profile refuses the run. If a task finds itself wanting a default, it has found the failure mode FR-001 exists to prevent.
- **Unknown stays unknown.** Every check names its own unresolved condition, and a signal the dump could not read is an unresolved coverage row naming what was missing — never a pass, a fail or a silent skip. A task that makes a check "simpler" by treating a null as a pass has reintroduced the macro's worst behaviour.
- **One finding per failing check per document**, carrying every subject and naming every instance, contributing **one** to its severity count. This is the only counting rule in the feature.
- **Nothing is rebuilt and no sheet is activated.** `ForceRebuild3` stays denied and this feature adds no exemption; the report says that rebuild-error counts are as the documents stood.
- **Three gates prove the refactors were refactors**, and each has its own task with none of this feature's code in it: T011 (every `checks/rms` test and `rms-*` golden unedited), T028's acceptance (`ModelCheckHostTests` unedited) and T030's acceptance (the Model check page's contract and injection tests unedited).
- **The IR bump happens once**, in Foundational, covering the model fields, `CutListItem` and all eight drawing models, because the additivity rule requires one minor bump made in both declarations together. The dumpers that fill those models stay in US1 and US2, so the delivery order `plan.md` states is unchanged.
- **The tab registers no MCP tool.** If `test_mcp_server.py`'s function-list assertion or `CliProfileWriterTests` needs an edit, something has been added that should not have been.
- **`standards.release` is not a seventeenth check.** It is the family's summary coverage item, always present, excluded from the sixteen-row `checks[]` array and from every waiver.
- **No task in this feature carries `[K]`.** No provider is constructed and no API key is read on any path; T093 proves it by making the provider factories raise.
