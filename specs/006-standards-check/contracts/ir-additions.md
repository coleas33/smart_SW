# IR 1.4.0 Additions

Every field and every model this feature adds, the interop member it comes from, the dump
phase it is written in, and its null rule. Normative alongside feature 001's generated
`contracts/ir.schema.json`, which is regenerated by
`python -m swreview.ir.schema --write specs/001-agentic-design-review/contracts/ir.schema.json`
in the task that makes the bump; `tests/unit/test_schema_sync.py` fails on drift and the C#
`IrSerializerTests` mirror is updated in the same task.

## The additivity rule

Applied to **every** row in this file, with no exceptions (FR-023):

1. Optional, with a default.
2. Absent from the `required` set in both serializers.
3. **Omitted when null.** The two sides do this differently and the difference is named here,
   because it is a task and not a convention:
   - **Python**: `omit_when_null`, as `ManifestEntry._omit_null_1_3_0_fields` already does.
   - **C#**: `PackageSerializer` is configured globally with
     `DefaultIgnoreCondition = JsonIgnoreCondition.Never` - deliberately, on Principle I
     grounds ("nulls are evidence") - and **no property in the extractor carries a
     `JsonIgnore` attribute today**. Each new **scalar** C# property therefore gets
     `[JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)]`, which is the **first
     per-property override of that global**. It is safe exactly here and nowhere else: every
     one of these fields re-states its own absence as a `Gap`, so omitting the null loses
     nothing a reader needs, whereas omitting an existing null would.
   - **C# arrays**: `WhenWritingDefault` does **not** omit an empty `List<T>` - only a null
     one - so `CutListItems` and `Drawings` are `List<T>?` defaulting to null, nulled when
     empty before serialization, and carry `WhenWritingNull`. `ExtractorInfo._omit_empty_phases`
     is **not** a cross-language precedent for this: it is a Python `@model_serializer` only,
     and the C# `ExtractorInfo.Phases` is a plain `List<DumpPhase>` that writes `"phases": []`.
4. The schema minor version is bumped **once**, 1.3.0 to 1.4.0, in
   `reviewer/src/swreview/ir/models.py` and
   `extractor/SwReview.Extractor/Ir/EvidencePackage.cs` **together**.
5. The feature 001, 002 and 003 golden fixtures are **byte-identical** afterwards (SC-004). A
   package that carries none of this feature's evidence serializes exactly as it did, because
   every addition is omitted - **on both sides**. A C# test asserts that a package with no
   cut-list and no drawing evidence serializes to bytes identical to the pre-1.4.0 output; it
   is the only thing that proves point 3's C# half.
6. **The bump is an input to feature 005's package-reuse key, and that is stated rather than
   discovered.** `Dump/ReuseKey.cs` includes `schema_version` in the canonical form, so every
   package dumped before 1.4.0 stops matching for reuse and the next pilot run re-dumps
   instead of reusing. That is **correct** - the schema differs - and it is named so nobody
   debugs it. The cross-language pin diverges silently if only one side is edited: the Python
   side derives the canonical form from `SCHEMA_VERSION` (`tests/support/packages.py`), while
   `extractor/SwReview.Extractor.Tests/ReuseFixture.cs` hard-codes `"1.3.0"`. The bump task
   edits `ReuseFixture.cs` and **both** pinned canonical-form strings
   (`reviewer/tests/unit/test_reuse_key.py`, `extractor/SwReview.Extractor.Tests/ReuseKeyTests.cs`)
   in the same commit, which is what that test's own comment asks for.

Both serializers still forbid unknown members, so a 1.4.0 package is readable only by 1.4.0 or
later builds; a 1.3.0 package loads in a 1.4.0 build.

**Verification marks.** VERIFIED = present with that signature on the installed
`SolidWorks.Interop.sldworks` / `.swconst` **32.5.0.48** (SOLIDWORKS 2024 SP5), by reflection
on 2026-09-16. It does not mean the member behaves as documented at runtime; where a runtime
question remains, the probe that settles it is named and the null rule says what the dump
records if the answer is no. Full detail in `research.md` R3.

## 4. Identity and persistent references (FR-026)

Every record in sections 2 and 3 carries a package `id` in the existing style
(`cut:NNNN`, `dsh:NNNN`, `dvw:NNNN`, `ddm:NNNN`, `dan:NNNN`, `dnt:NNNN`, `drv:NNNN`),
allocated in traversal order, **plus** `persist_ref` and `persist_ref_scope` when SOLIDWORKS
gives one.

**A null `persist_ref` is the statement FR-026 requires.** It says the `id` is a within-dump
identity, stable inside this package and not across dumps, and a consumer can therefore tell a
persistent reference from one and never present the second as the first. Two things follow
from it, and both are tested:

- `Subject.showable` is false, and the page renders **no** Show control for that subject
  rather than one that reports `ok: false` every time (FR-031).
- A standards exception's fingerprint hashes the record's **content**, not its `id`, so a
  re-dump that renumbers the ids does not invalidate a waiver.

PROBE-10 records which of the seven kinds SOLIDWORKS actually gives a reference for; until it
answers, every one of them is written as null and the page shows no Show control for them.

**What the `DrawingSheet.source` stamp does and does not move.** Five feature 001/002/003 golden
fixtures carry PDF-ingested `DrawingSheet` rows (`angle-not-length`, `cover-blind-tap`,
`mixed-units`, `plate-stack`, `shaft-bore`). They are **static input files that nothing
rewrites**, and the new field is absent from them and therefore omitted, so they stay
byte-identical and still load - the stamp reaches only sheets the ingest writes from now on.
What the stamp *can* move is any artefact **regenerated from the ingest**: the
`reviewer/tests/golden/test_golden/*.yml` baselines if the field reaches a summary or a coverage
row, and any test that rebuilds a package through `ingest/package_builder.py` and compares
bytes. Quickstart Scenario 0 is where that is measured, and `git status --porcelain
reviewer/tests/golden` printing nothing is the assertion.

## 5. New gap `entity_kind` values

`assembly_exploded`, `rebuild_error_count`, `mass_override`, `component_transparency`,
`component_visibility`, `component_pattern`, `mate_entity_reference`, `sketch_text`,
`cut_list_folder`, `cut_list_body_count`, `cut_list_exclusion`, `drawing_sheet`,
`drawing_sheet_views`, `drawing_view`, `drawing_referenced_document`, `dimension_override`,
`dimension_unit`, `annotation_identity`, `annotation_dangling`, `note_text`,
`revision_table_read`.

Each names one `entity_id` where one exists (the component, the document, the record's id), and
**each has a producing condition in a row of this file**, so a test that enumerates the new
kinds can exercise every one of them. `cut_list_folder` is emitted when a body folder's
`IFeature.GetTypeName2` or `IFeature.GetSpecificFeature2` could not be read, which PROBE-8 makes
likely enough to name; the folder is still recorded, with the gap saying what was missing.

There is deliberately **no `drawing_persist_ref` kind.** Section 4 is the design: a missing
persistent reference is a **null `persist_ref`**, which is the statement FR-026 requires, and a
gap beside it would say the same thing twice.

**One existing gap changes, and its message changes with it.** The standing gap every dump
writes today - `"The native extractor does not read drawing sheets; they come from the PDF
ingest."` - becomes **conditional**: emitted only when the drawing phase did not run, and then
naming the profile that skipped it (FR-024). Two consequences, both stated rather than
discovered:

- The **message** changes in every `full` and `model_check` package that still carries the gap,
  so the gap set is not byte-identical. **No existing test asserts that string**: the only test
  on this gap today, `PackageWriterTests.Build_RecordsThatDrawingsAreNotExtractedNatively`,
  asserts the entity kind and the gap kind alone, and it keeps passing unedited (its name
  becomes stale). The message assertion is therefore **added** in the test task that precedes
  the change (T016), not an edit to an existing one.
- A `full` dump of a **drawing root** now runs the drawing phase, so it **loses** the gap
  entirely, and a `full` dump of a weldment or sheet-metal part now runs the `cutlist` phase,
  so it may **gain** `cut_list_folder`, `cut_list_body_count` or `cut_list_exclusion` gaps.

SC-004's gap clause is narrowed to what is actually invariant and testable (spec SC-004,
`quickstart.md` regression gate 4), and the narrowing agrees with the bullet above rather than
contradicting it: a `model_check` dump of a part or assembly produces the same gap set **except
for the drawing gap's new message** - the same gap kinds, entity kinds, entity ids and count,
with the one changed message asserted separately as the profile-naming string, because a
`model_check` dump never runs the drawing phase and therefore always carries that gap; a `full`
dump of a part or assembly produces the same gap set except for that same message and any gap
the new `cutlist` phase records; and a `full` dump of a drawing root omits the drawing gap,
which is its own assertion. **Nothing in this feature claims a byte-identical gap set.**

## 6. Phases and profiles

`PackageWriter.PhaseOrder` becomes:

```
document, manifest, mate, feature, equation, cutlist, drawing, hole, fastener, face, body
```

| Profile | Phases run |
|---|---|
| `full` | document, manifest, mate, feature, equation, cutlist, hole, fastener, face, body - ten; plus `drawing` **only** when the root document is a drawing, recorded `skipped` otherwise |
| `model_check` | document, manifest, mate, feature, equation |
| `standards` | document, manifest, mate, feature, equation, **cutlist**, and **drawing** when the root document is a drawing |

`standards` extends `model_check` and still skips hole, fastener, face and body - the four
phases that read face geometry, tessellate every body and write mesh files, which is most of a
dump's cost and none of which any standards check reads. `full` also runs `cutlist`, and
`drawing` for a drawing root, so **a full extract is never less complete than a standards
one** (FR-027).

**A consumer decides from the phase rows, not from the profile name.** A phase that never
started is recorded as `skipped` with no elapsed time, which is exactly the fact a reader needs
when a package comes back thin. `swreview check standards` refuses a package whose `cutlist`
row - or, for a drawing, whose `drawing` row - is `skipped`, naming the profile that produced it
and the phases that are missing, and accepts **any** package that actually ran them, whatever
profile that was (FR-043).

**Stated consequence**: every package written after this feature carries two more phase rows.
Golden fixture files on disk are static and stay byte-identical; the edits the two new phases
force are **named in the task that adds them** rather than discovered during it:

- `reviewer/tests/unit/test_ir_phases.py` and the C# `IrSerializerTests` mirror, which pin the
  full phase list.
- **`DumpPhase.name`'s field description** in `reviewer/src/swreview/ir/models.py`, which
  enumerates the nine current phase names verbatim and feeds the generated contract. Leaving it
  stale makes the regenerated 1.4.0 schema describe a phase vocabulary that no longer matches
  `PackageWriter.PhaseOrder`, and `test_ir_phases.py` already asserts against that description's
  text, so the omission would also be a silent test dependency.
- The matching XML doc on `extractor/SwReview.Extractor/Ir/Manifest.cs`, so the two sides say
  the same thing.

## 7. Drawing-rooted traversal (FR-025)

Not an IR field, but it is what fills `documents[]`, the manifest and
`design.drawing_document_ids` for a drawing root, so it belongs with the additions.

- `ComponentTreeDumper` gains a **drawing branch**: for each document a view on any sheet
  references **and that is already loaded**, it walks that document's component tree exactly as
  it walks an assembly root today, producing one subtree per referenced model under a
  synthesized forest root.
- `PackageWriter.DocumentPaths` gains the drawing's own path and every referenced model path,
  so drawing documents enter `documents[]` and the **manifest** for the first time.
- `BuildDesign` populates `design.drawing_document_ids`, which has existed in the IR since
  feature 001 and has never been set by a native dump.
- `design.root_assembly_document_id` holds the **root document's** id whatever its kind -
  already true for a part opened alone since feature 003 - and for a drawing root it is the
  drawing's id. The field's name is a misnomer feature 003 made; renaming a required IR field
  is a breaking change and the value is unambiguous, so it is not renamed here.
- **Nothing is opened, loaded, resolved or activated** to do this (FR-044). A referenced
  document that is not loaded is a `drawing_referenced_document` gap naming it, and every part-
  and assembly-scope check for it is unresolved coverage naming that gap.
- **The dump does not discover the drawings of an open model.** A drawing enters a package only
  when the drawing itself is the dumped document, or when the package was produced elsewhere and
  handed to the command line.
