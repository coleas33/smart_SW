# Contract: Tolerances

Normative for FR-021 to FR-025, User Story 8 and SC-007, SC-008.

## 1. IR 1.5.0

`HoleWizardData`, `ModelDimension`, `ModelAnnotation` as `data-model.md` section 10:
`Hole.wizard` optional and omitted when null; `model_dimensions` and `model_annotations`
optional and omitted when empty; `SCHEMA_VERSION = "1.5.0"` in both serializers; `ir.schema.json`
regenerated by `ir.schema.export_schema()` and kept in step by `test_schema_sync.py`. A 1.4.0
package loads and re-serializes to its own bytes; a 1.5.0 package with none of the new members is
byte-identical to what a 1.4.0 build writes except `schema_version`.

## 3. Profile version 2: the general tolerance

```yaml
version: 2
# ... every version 1 section, unchanged ...
general_tolerance:
  linear:
    - {over_mm: 0.5, up_to_mm: 6.0, plus_minus_mm: 0.15}
    - {over_mm: 6.0, up_to_mm: 30.0, plus_minus_mm: 0.25}
  angular_deg: 0.75
hygiene:
  part_number_property: "Fictional Number"
  description_property: "Fictional Summary"
```

Values are placeholders; the company's block is the owner's to write. Bands are contiguous and
ordered, `over < nominal <= up_to` selects one, and a nominal outside every band has no general
tolerance. The loader refuses overlapping or unordered bands naming them.

## 4. The resolver (`checks/tolerances.py`)

`resolve_tolerance(package, profile, subject) -> ResolvedTolerance | UnresolvedTolerance`, the
sources walked in precedence and the first that binds returned:

| # | `SourceKind` | Binds when | The `Dimension` built |
|---|---|---|---|
| 1 | `drawing` | a feature 011 native dimension or hole callout references one of the subject's faces | 011's own |
| 2 | `annotation` | a `ModelAnnotation` of kind `gtol` whose `attached_persist_refs` include one of the subject's face persist refs; a position or concentricity symbol for `hole_position`, a size frame otherwise | zone value as a `limits`-free `Dimension`, read through `permitted_radial_offset_mm` |
| 3 | `model_dimension` | a `ModelDimension` in the subject's document, `diameter` or `radius`, nominal equal to the subject's size within 1e-6 mm, unique in the document | its `tolerance`, `source.persist_ref` the dimension's |
| 4 | `hole_wizard` | `Hole.wizard.fit_class_raw` names an ISO 286 class `checks/iso286.yaml` carries (`H6` to `H11`, `h6` to `h11`) for the subject's nominal | `limits` from the table, `source` citing the hole and the class |
| 5 | `general` | a `hole_size` or `pin_size` subject, no source 1 to 4, a version 2 profile with a band containing the nominal | `symmetric`, `upper = plus_minus`, `source` citing `general_tolerance` in the profile identity |

`hole_position` is never bound by source 5. A lower source that also binds is listed in
`also_found`; an `also_found` whose limits differ from the chosen one's sets `conflict`, which the
consuming check adds as a coverage limit. A subject no source binds returns `UnresolvedTolerance`
with one `(source, why)` per source, for example `("drawing", "not available before feature 011")`,
`("hole_wizard", "no fit class recorded for hol:0018")`, `("general", "the profile is version 1")`.
Nothing else produces a limit.

## 5. The ISO 286 table (`checks/iso286.yaml`)

IT5 to IT11 over the size ranges up to 120 mm and the `H` and `h` classes (fundamental deviation
0), entered from ISO 286-1 with the source line; `H7` on a 10 mm nominal is `+0.015/0`. A class the
table does not carry is recorded and cited and binds nothing.

## 6. Drawing tolerances (FR-024)

Source 1 is a function slot, `drawing_tolerance(package, subject) -> Dimension | None`, returning
`None` with the reason "not available before feature 011" until 011 lands native drawing
dimensions; 011 fills it and the stack-up and `refs.resolve_dimension` (for `check_fit` and
`check_axial_stack`) read the same records under the same citation rules.
