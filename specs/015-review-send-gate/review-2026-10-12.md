## Open finding: FR-041 after the re-run’s session replacement

FR-041 and `recheck.md` sections 2 and 6 require any failed or cut-off re-run to leave the earlier
canonical `session.json` for restoration. The planned shared `close_waiting()` calls today’s
`ReviewRun.finalize()`, whose actual order is:

1. `save_session(session, session_path)` (`agent/runner.py:1372`);
2. `write_attention_record(...)` (`:1373`), which can raise;
3. `session.ended` emit (`:1383`), which can raise.

A failure or kill after step 1 leaves the new re-run record as canonical. Copying the earlier
record to an index does not keep it canonical. T094 only kills before the atomic replacement,
so its current cases cannot expose this window. This differs from an apply, whose contract
already defines the before-save and after-save records separately.

**Owner decision pending; FR-041 is unchanged.** No US4 implementation proceeds past this finding
until the owner answers. It does not block the current US1 milestone. Concrete choices:

- **Atomic replacement completes the re-run.** Define a commit point, preserve the earlier record
  at its index, and specify recovery from the whole new record after that point. Add failure and
  kill cases before and after replacement, plus attention/event failures. This is the smaller
  implementation, but changes FR-041’s blanket promise and needs the owner’s approval.
- **Preserve the earlier canonical record on every incomplete re-run.** Prepare/stage the new
  artifacts and introduce a transaction/recovery protocol that leaves or restores the earlier
  record if completion is interrupted. This preserves the promise, but needs more state, recovery
  rules, tests and coordination with the shared finalization path.

An undo save only on raised errors is insufficient: it does not run after a kill and can itself
fail. It is not a solution to the current crash guarantee.
