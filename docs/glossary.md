# Glossary

The project's own terms, as a newcomer meets them in the specs, the task lists and the Task
Pane. Each entry links to where the term is defined; that file is authoritative. Where a term
is used in more than one sense, every sense is listed. For how the parts fit together, read the
[architecture overview](architecture.md).

| Term | Definition | Defined in |
|---|---|---|
| ADR | An architecture decision record, numbered and not edited after acceptance except to mark it superseded. | [docs/adr/README.md](adr/README.md) |
| AI guidance | The label the Review tab and the report put on text the model wrote (explanations, model-written coverage), as against "Checked by code". | [013 sources.md](../specs/013-engineer-first-review/contracts/sources.md), `report/review_words_v1.yaml` |
| Answer key | A benchmark case's list of known defects and correct conditions that a review is scored against; never shown to the reviewer. | [014 answer-key.md](../specs/014-design-review-eval/contracts/answer-key.md), [benchmarks/README.md](../benchmarks/README.md) |
| Arm | One side of a study: `off`, `on`, or `baseline` (a study with no lever under test). | [005 ab-harness.md](../specs/005-llm-efficiency/contracts/ab-harness.md) section 2, `agent/settings.py` `ARMS` |
| Ask tab | A hidden Task Pane tab that runs an external command-line assistant in a pseudo-console with read-only tools (`swreview mcp`). Hidden since 2026-09-19 (`AskTabShown = false`). | [002 spec](../specs/002-task-pane-assistant/spec.md), `extractor/SwReview.AddIn/TaskPaneControl.cs` |
| Attention, ranking | The total order a finished review's findings are shown in: a fixed list of keys compared in turn (suppressed last, needs judgement first, consequence class, status, severity, reach, carried over, ids), with no weights. Recorded in `attention.json`. | [007 attention.md](../specs/007-attention-policy-gate/contracts/attention.md) |
| Bridge, tool service | The named-pipe channel through which the Python side asks the running SOLIDWORKS to capture, measure, run interference or read a drawing, with a per-launch secret and a fixed command list. The in-process end is the add-in's tool service; the console host's `serve` is the out-of-process end. | [bridge PROTOCOL.md](../reviewer/src/swreview/bridge/PROTOCOL.md), [Serve/PROTOCOL.md](../extractor/SwReview.Extractor.Console/Serve/PROTOCOL.md) |
| Carried over | A finding brought forward from a previous session of the same design; it ranks below an otherwise identical fresh one. | [007 attention.md](../specs/007-attention-policy-gate/contracts/attention.md) section 1 |
| Case, twin, held out | A benchmark case is one fictional package with its answer key (and, for some, scripted answers). A clean twin is a copy of a core case with every planted defect removed. Held out marks a graded item not used to tune the reviewer. | [014 cases.md](../specs/014-design-review-eval/contracts/cases.md), [014 spec](../specs/014-design-review-eval/spec.md) "Terms" |
| Check family | A catalogue of rules with an evaluation entry point and a report layer; the Resilient Modeling rules (`checks/rms/`) and the release standards (`checks/standards/`) are the two, over shared machinery in `checks/rules/`. | `reviewer/src/swreview/checks/rules/family.py` |
| Checks first | Lever 5 (`prerun_checks`): the checks whose scope the package already decides run before the model's first turn, through the same tool dispatch the model uses, and the model opens on a digest of what they found. The pane's default since 2026-09-22; off by default on the command line. | [008 checks-first.md](../specs/008-checks-first-review/contracts/checks-first.md), `reviewer/src/swreview/prerun.py` |
| Constitution | The project's governing rules (Principles I to VI, technical constraints, workflow); it supersedes every other guidance file. | [constitution.md](../.specify/memory/constitution.md) |
| Coverage | The record of what a review checked, skipped, left unresolved, failed or held out of scope, in those five buckets. Unsupported or failed checks stay visible as coverage, never dropped. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 3, constitution Principles I and VI |
| Disposition | The engineer's decision on a finding: `accepted`, `rejected` or `deferred`, with a note, who and when. Written by the engineer, never by the reviewer; a deferred one can later be accepted or rejected. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) sections 3 and 5 |
| Engineering context | Requirements and applied forces an engineer attaches to a saved extracted part, occurrence or face, stored as immutable, confirmed revisions in a private store and supplied to a review as bounded read-only context. | [016 spec](../specs/016-engineering-context/spec.md) |
| Evidence package, package | The IR of one extracted design: `package.json` (plus `meshes/` and `captures/`) in a run folder, with every entity's persistent reference and a `gaps` list for what could not be read. In the benchmark, "package" also names a case's folder under `benchmarks/packages/`. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 2, [ir.schema.json](../specs/001-agentic-design-review/contracts/ir.schema.json) |
| Evidence request | A question the review asks the engineer (for example which drawing to use, or an input the package lacks); open until answered, and anything that depends on it stays `unresolved`. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 3, [009 questions.md](../specs/009-engineer-workspace/contracts/questions.md) |
| Exception, waiver | An engineer's acceptance of a finding's condition, bound to the reviewed geometry and configuration by a fingerprint; it goes to `needs_review` when either changes. Blanket exclusions are prohibited. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 3, constitution Principle VI |
| Extract tab | The Task Pane tab with three buttons that write an evidence package, add interference results or capture the selection by hand, for command-line use. The Review tab extracts automatically. | `extractor/SwReview.AddIn/TaskPaneControl.cs` `ExtractPurpose` |
| Fictional data | The only kind of design data the public repository may hold: no real design, part or drawing number, company, customer, person, vault or network path, real standards profile, recording or key. Fixtures use invented names. | [AGENTS.md](../AGENTS.md) rule 2, [config/standards.example.yaml](../config/standards.example.yaml) |
| Finding | One reported condition with its check id, status (`demonstrated`, `suspected`, `unresolved`, `checked_within_scope`), severity, affected components or drawing locations, inputs, calculation, coverage limits, recommended action and the engineer's disposition. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 3, constitution Principle I |
| Gap | A recorded reason a value could not be extracted; the value stays `null` and is never defaulted. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 2 |
| Gate | (1) The test gate: the commands that must pass before every commit. (2) A slice's gate: the named checks that must pass on `main` before the next slice merges. (3) The procedural gate, lever 11 (below). (4) The send gate of feature 015 (below). The word also appears for the guards' allowlists and the remodel geometry check (`GateResult`). | [AGENTS.md](../AGENTS.md) "Gates before every commit", [014 plan.md](../specs/014-design-review-eval/plan.md) "Delivery order" |
| Golden fixture | A saved IR dump plus its expected findings, kept for regression of extraction and checks; a change to the IR schema or a check updates or adds one. | constitution Principle III |
| IR | The intermediate representation: the typed, versioned model of a design that extraction writes and every check reads, outside SOLIDWORKS so a review can be replayed and tested without a seat. A consumer rejects an unsupported major version. | constitution Principles II and IV, [001 data-model.md](../specs/001-agentic-design-review/data-model.md) |
| Ledger | (1) The results ledger of efficiency studies: the block `swreview benchmark compare --into` writes into `docs/llm-efficiency-options.md`, with `ledger.json` and `ledger.md` per comparison. (2) The usage ledger: the per-session accumulator of token usage read from the event stream (`UsageLedger`). | [llm-efficiency-options.md](llm-efficiency-options.md), [005 ab-harness.md](../specs/005-llm-efficiency/contracts/ab-harness.md), `reviewer/src/swreview/agent/events.py` |
| Lever | One named efficiency setting in `EfficiencySettings` (fourteen names), each behind a flag and adopted only on measured evidence; for example lever 5 is checks first and lever 11 the procedural gate. | [005 levers.md](../specs/005-llm-efficiency/contracts/levers.md), [llm-efficiency-options.md](llm-efficiency-options.md) |
| Lightweight component | A SOLIDWORKS component loaded without its full model. The IR records it as `lightweight` and every check that needs it is reported unresolved rather than silently skipped. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 2, [001 spec](../specs/001-agentic-design-review/spec.md), [feature-request-resolve-lightweight.md](feature-request-resolve-lightweight.md) |
| Live test | A test marked `live` that calls a real, paid provider API; deselected by the gate's `-m "not live"`, skipped without a key, and run only when asked. | `reviewer/pyproject.toml` markers, [AGENTS.md](../AGENTS.md) rule 3 |
| Model check tab | The Task Pane tab that grades the open part against the Resilient Modeling rules with no model and no key, read-only (`POST /checks/rms`). | [003 model-check.md](../specs/003-resilient-modeling/contracts/model-check.md) |
| Noise floor | In the pane study, the smallest true drop in model-judgement recall the study detects with 80% power, found by simulation and printed with the verdict. | [014 spec](../specs/014-design-review-eval/spec.md) "Terms", [014 verdict.md](../specs/014-design-review-eval/contracts/verdict.md) section 9.7 |
| Owner decision (NNA) | A decision by the project owner, cited as a number and a letter, for example `59A`: the number is the question or issue, the letter the option chosen (options are lettered with the recommended one first, so A is usually the recommended option; B or C records an alternative). Recorded in the feature's `research.md`. Numbers are not unique across features, so cite the feature with the number. | [docs/adr/README.md](adr/README.md), [014 research.md](../specs/014-design-review-eval/research.md) section 1 |
| Pane defaults | The settings every pane review runs with (four levers and two model-view settings, decision 3A of feature 014); `--pane-defaults` applies them on the command line. | [014 spec](../specs/014-design-review-eval/spec.md) "Terms", `agent/settings.py` |
| Part roles | Whether each part is custom, bought or unclear, decided from the standards profile's `part_roles` section; bought parts are not graded as made parts, and an unclear one is asked about. | [013 part-roles.md](../specs/013-engineer-first-review/contracts/part-roles.md) |
| Persistent reference | The opaque SOLIDWORKS id every IR entity carries (with the document it is scoped to) so a finding can point back to the exact entity. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md), constitution Principle IV |
| Pilot | (1) The pilot deployment of the product on the pilot workstation, whose success criterion is at least 60 minutes of net engineering effort saved per design. (2) `benchmarks/sets/pilot.json`, the lever studies' smoke set. (3) The paid pilot of feature 014: scored off-arm runs whose measurement (`swreview benchmark pilot`) sets a study's size and cost. | constitution Principle VI, [benchmarks/README.md](../benchmarks/README.md), [014 verdict.md](../specs/014-design-review-eval/contracts/verdict.md) section 10 |
| Procedural gate | Lever 11 (`procedural_gate`): the pre-run plus the standards call, with a brief replacing the checks-first digest. Off by default; the pane exposes no control for it. | [007 gate.md](../specs/007-attention-policy-gate/contracts/gate.md) |
| Remodel tab, re-modeler | The Task Pane tab and feature that copy the open part into the run folder and reorganize the copy under the Resilient Modeling Strategy, then show the change list, the grade and the geometry comparison. The original file is never opened for writing; the result is a proposal. | [004 spec](../specs/004-resilient-remodeler/spec.md), constitution Technical Constraints exception 2 |
| Replay | Re-running a recorded review's model requests offline, with no provider, to measure what a change does to what the model reads. | [008 replay.md](../specs/008-checks-first-review/contracts/replay.md) |
| Review tab | The Task Pane tab that extracts the open assembly, runs the reviewer and shows its summary, questions, findings grouped by type and coverage. | [002 spec](../specs/002-task-pane-assistant/spec.md), [009 spec](../specs/009-engineer-workspace/spec.md), [013 grouped-list.md](../specs/013-engineer-first-review/contracts/grouped-list.md) |
| RMS, resilient modeling | The Resilient Modeling Strategy (Richard Gebhard, 2013): rules for robust part, assembly, equation and drawing modeling, evaluated as deterministic findings by the `rms.*` checks. | [003 spec](../specs/003-resilient-modeling/spec.md), [003 rules.md](../specs/003-resilient-modeling/contracts/rules.md) |
| Run folder, run root | A run folder holds one review, check or remodel run (`package.json`, `session.json`, `report.md`, ...), named `<yyyyMMdd-HHmmss>-<doc>` with a `-check`, `-standards` or `-remodel` suffix where it applies. The run root is the folder they live in, set in the pane settings; the backend refuses a run folder outside it. | [002 pane-host-messages.md](../specs/002-task-pane-assistant/contracts/pane-host-messages.md), [chat-api.md](../specs/002-task-pane-assistant/contracts/chat-api.md) |
| Saved set | `benchmark-set.json`, the copy of the set a benchmark run reviews, written into the run folder before any review with paths relative to the checkout. | [014 provenance.md](../specs/014-design-review-eval/contracts/provenance.md) section 6.1 |
| Seat, pilot workstation | A seat is a licensed SOLIDWORKS installation; the pilot workstation is the machine with the licensed seat where the add-in is installed and seat tasks run. A machine without a licence never starts SOLIDWORKS. | [workstation-runbook.md](workstation-runbook.md), [AGENTS.md](../AGENTS.md) rule 5 |
| Send gate | Feature 015's checkbox "Send to the model when the checks finish", beside Review and ticked by default. Unticked, Review runs the code checks only and waits (`awaiting_send`) with a Send to model button and the estimated request size; nothing reaches a provider until Send, and no key is needed. | [015 spec](../specs/015-review-send-gate/spec.md) (decisions 59A to 62A), [015 review-flow.md](../specs/015-review-send-gate/contracts/review-flow.md) |
| Session | One review's record, `session.json`: steps, evidence requests, findings, coverage, timing and usage. Its event stream is `events.jsonl`. | [001 data-model.md](../specs/001-agentic-design-review/data-model.md) section 3, [review-session.schema.json](../specs/001-agentic-design-review/contracts/review-session.schema.json) |
| Slice | One delivery increment of a feature's plan: test-first, landed on `main` in order, with its own gate passing before the next slice's first merge. | [014 plan.md](../specs/014-design-review-eval/plan.md) "Delivery order" |
| Standards profile | The company's release-standards configuration (library prefixes, data card, part numbering, revision, material, tolerances, hygiene, drawing rules, part roles), a YAML file kept outside the repository; the repository holds only a fictional example. | [006 profile.md](../specs/006-standards-check/contracts/profile.md), [config/standards.example.yaml](../config/standards.example.yaml) |
| Standards tab | The Task Pane tab that checks the open part, assembly or drawing against the standards profile and says whether it is ready to release, with no model and no key, read-only (`POST /checks/standards`). The README also calls it the Standards check tab. | [006 standards-check.md](../specs/006-standards-check/contracts/standards-check.md) |
| Study | One lever, one provider, one model, one effort, three repetitions per arm, each repetition its own `swreview benchmark run`; the pane study compares the pane defaults on and off. | [005 ab-harness.md](../specs/005-llm-efficiency/contracts/ab-harness.md) section 2, [014 verdict.md](../specs/014-design-review-eval/contracts/verdict.md) |
| Task Pane | The SOLIDWORKS add-in's docked panel. Visible tabs, in order: Review, Extract, Model check, Remodel, Standards; Ask is built but hidden. | `extractor/SwReview.AddIn/TaskPaneControl.cs` |
| Tokenizer pin | The `o200k_base` vocabulary the reviewer's own token counts use (the replay, the Send estimate), fetched once into a per-user cache by `swreview tokenizer fetch` and checked against a fixed sha256 (`ENCODING_SHA256`); it is not in the repository. | [008 tokenizer.md](../specs/008-checks-first-review/contracts/tokenizer.md), `reviewer/src/swreview/tokens.py` |
| Verdict | (1) The engineering conclusion a check reaches, which only tested code may compute. (2) The standards release verdict: `ready`, `not_ready` or `ready_coverage_incomplete`, with every bucket's count. (3) The pane study's verdict from `benchmark compare`: `quality loss`, `no 10-point loss` or `inconclusive`. | constitution Principle II, `reviewer/src/swreview/checks/standards/verdict.py`, [014 verdict.md](../specs/014-design-review-eval/contracts/verdict.md) |
| `[W]` task | A task that needs the pilot workstation: SOLIDWORKS 2024 with the add-in registered and a real document open. Done and recorded by hand on the seat, never on another machine. | [005 tasks.md](../specs/005-llm-efficiency/tasks.md), [AGENTS.md](../AGENTS.md) rule 5 |
