# Holes

What stands between smart_SW and an engineer's benefit, one row per hole, every status kept. A
hole is not "open task X is open" (that is a row of [`capabilities.md`](capabilities.md)): it
names a gap no open task covers, or a reason an open task, once done, still will not bring an
engineer the benefit. Ids are permanent, `H-<lens>-<nnn>`; a hunter matches the register before
it mints one. Refuted, wontfix and merged rows stay, so later runs do not hunt them again. The
roadmap that orders them is [`README.md`](README.md).

**Lenses:** a, validation; b, usefulness; c, workflow; d, trust; e, cost and performance;
f, sustainability; g, feedback loop.

## Statuses

| Status | What it carries |
|---|---|
| `open-verified` | a skeptic confirmed the evidence from the code and the records |
| `open-plausible` | likely, but not confirmed from the code and the records |
| `closed-offline` | the test name and the PR |
| `closed-validated` | the sitting date, the step id and the ticked seat task |
| `refuted` | the refuting evidence |
| `wontfix` | the decision id |
| `merged into H-x-nnn` | the hole it was folded into |

A validation hole (lens a) closes only as `closed-validated`.

## Score anchors

Each open hole is scored 1 to 3 on six factors; the total, 6 to 18, orders the work, and the
roadmap's ordering rules break ties. A score changes only with newly cited evidence, and the
change log says which score changed and why.

| Factor | 3 | 2 | 1 |
|---|---|---|---|
| **I**, impact on the engineer | without it the engineer gets no benefit, is misled, or loses work | the benefit is cut, or time is lost, on each review it touches | cosmetic, or felt only by the developer or the plan |
| **F**, frequency | every review or every design | some designs or some reviews (drawings, big assemblies) | rare, or an edge case |
| **C**, confidence | `open-verified`, with direct evidence | `open-plausible`, with indirect evidence | inference only |
| **$**, cost, inverted | an owner decision, a sitting step, or under a day offline | a few days offline, or part of one sitting | a new feature, several sittings, or a constitution amendment |
| **R**, risk removed | removes the risk of building on a false premise (the tool not helping) or of harming the engineer's files or trust | removes a known failure mode | small |
| **U**, what it unblocks | on the critical path to M0's exit | unblocks a later milestone or several holes | nothing else |
